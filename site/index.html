REHUB

Drop in OT evidence. Get an investigation you can explain. It runs on your own machine and sends nothing out.

curl -fsSL https://raw.githubusercontent.com/Ani07-05/rehub-engine/main/scripts/install.sh | sh

Needs Docker with Compose v2. The first run downloads about 280 MB. Other ways to install.

What happened

10.0.0.66 (unidentified device) sent a PLC stop command to 10.0.0.30 (Siemens AG controller) and 2 register write commands to 10.0.0.20 (Telemecanique Electrique controller, pump program).

Two independent tools agree on all of them.

In the pump PLC program these writes change Setpoint, PumpSpeed and SpeedLimit, which feed ReliefValve and PumpRun.

Written by ReHub from a synthetic demo capture and a sample PLC program that ship with it. Your evidence stays on your machine.

Get it

curl -fsSL https://raw.githubusercontent.com/Ani07-05/rehub-engine/main/scripts/install.sh | sh
git clone https://github.com/Ani07-05/rehub-engine
cd rehub-engine
./scripts/install.sh --local

Needs Docker with Compose v2. The one line pulls the published image (about 280 MB, for Intel and Apple-silicon or Arm machines) and starts it in under a minute. From source builds the same image on your machine, which takes a few minutes the first time.

How ReHub knows

Every detection shows which tools saw it. Zeek saw the protocol action, Suricata matched a rule, tshark holds the packets, and your PLC program shows what the command touched. Agreement between independent tools is the confidence, and a detection only one tool reported is labelled that way.

What happens to your files

One path for every upload. Each stage answers one question and feeds the next.

Something you can hand to someone

The report prints to PDF or downloads as one HTML file with no scripts. It lists every detection with its evidence, what could not be verified, and a chain of custody with the SHA-256 of every file.

Local by design

Checked on the running installation, not just intended:

  • The engine has no way out. It parses your files on a network with no route out. From inside it, reaching the internet fails with "Network is unreachable" and names do not resolve.
  • One door, on this machine only. A small gateway forwards the web UI and publishes it on 127.0.0.1. The engine publishes no ports.
  • Locked down. Read-only root filesystem, every Linux capability dropped, no new privileges, memory and process limits.
  • Hostile files handled as hostile. Evidence is only ever served as a download, never shown as a page. File-derived text is never treated as HTML. PLC XML with entity declarations is rejected. Archives have size and file-count limits.
  • No telemetry, no cloud. Sign-in is off by default because it is local only; one flag turns on an access token.

What the install command does

It does

  1. Checks that Docker and Compose v2 are installed and running.
  2. Writes two files into ~/.rehub: compose.yml and .env.
  3. Starts two containers and waits until both are healthy.
  4. Runs a self-test: Zeek, Suricata and tshark on a built-in capture, checking the expected Modbus write is found.
  5. Prints the address and opens it.

It touches

  • ~/.rehub (the two files)
  • Docker containers rehub-engine-1 and rehub-gateway-1
  • Docker networks rehub_internal and rehub_edge
  • Docker volume rehub_rehub-data (your investigations)
  • The image ghcr.io/ani07-05/rehub-engine

No sudo. No changes to your PATH or shell profile. Nothing outside Docker and that one folder.

Read it first

The installer is one short file with the compose file inside it. Download it, read it, then run it. To pin an exact version, replace main in the address with a tag or commit.

curl -fsSL https://raw.githubusercontent.com/Ani07-05/rehub-engine/main/scripts/install.sh -o install.sh
less install.sh
sh install.sh

Remove it

sh install.sh --uninstall           # stop it, keep your investigations
sh install.sh --uninstall --purge   # also delete them

What it is not

  • It does not capture live traffic. It analyzes files you give it.
  • It does not give verdicts. ATT&CK for ICS techniques are candidates, because a capture cannot show whether a command was authorized.
  • It does not yet read every file type. Syslog, CSV asset and historian exports and tshark JSON are stored and hashed, and listed as not analyzed.
  • It is tested on macOS (Apple silicon) with Docker Desktop and on real public Modbus, S7 and DNP3 captures. The image is built for amd64 and arm64 (the build runs in CI), but Linux and Windows (WSL) installs are untested.
