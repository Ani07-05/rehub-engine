ReHub documentation

ReHub is a local, offline investigation engine for operational technology (OT) evidence. You give it a packet capture, tool logs or PLC project files. It runs Zeek, Suricata and tshark in one container, joins their output with the PLC logic, and answers in plain language first, with the proof one click away.

Description

An OT incident usually leaves evidence in several shapes: a capture from a mirror port, Zeek logs, Suricata alerts, and the PLC program itself. Each tool shows part of the story. ReHub reads all of them, normalizes the output into one event schema, and builds one investigation: which devices exist, who talked to whom, what looks wrong, what proves it, and a report you can hand to someone else.

It runs on your own machine. The analysis container has no route out: it cannot reach the internet or resolve names. Evidence is never uploaded anywhere.

Features

  • One upload, three tools. Zeek (protocol actions), Suricata (rule alerts) and tshark (packet details) run on the same capture. Zeek includes the CISA ICSNPP parsers for S7comm and EtherNet/IP.
  • Tool lanes. Every detection shows which tools saw it: Zeek, Suricata, tshark, or the PLC logic. Two independent tools agreeing is shown as corroboration.
  • Network joined to PLC logic. A Modbus register write is traced to the PLC variable it overlaps, the logic that reads it, and the outputs it drives. The address mapping (wire address N is %MW N) is shown as an assumption, not a fact.
  • One flow. Assets, Communication, Detections, Evidence, Report. Each step says which question it answers.
  • Two reading modes. Summary for the story, Investigator for the detail, over the same facts. Dark and light themes.
  • Evidence you can defend. Every file is fingerprinted with SHA-256. Each detection links to the file, the line and the packets behind it. The report downloads as one offline HTML file with no scripts.
  • Honest limits. Missing tools, capture loss, ambiguous hardware addresses and files that were not analyzed are listed under "What we could not verify". ATT&CK for ICS techniques are candidates, never verdicts.
  • Demo without hardware. A built-in pump station capture with a rogue device runs with one button.

What it is not

  • It does not capture live traffic. It analyzes files you give it.
  • It does not give verdicts. A capture cannot show whether a command was authorized.
  • It does not replace Zeek, Suricata or tshark. It wraps them and compares what they report.
  • It is not a multi-user server. It binds to loopback and is built for one analyst on one machine.

License

Changelog

ReHub v2 is pre-release. The version in the package is 0.2.0 and there are no tagged releases yet. What exists today:

AreaState
EngineSniffing by content, hashing, safe unpacking of zip, tar and gzip, adapters for Zeek, Suricata and tshark, correlation, ATT&CK candidates, PLC analysis and register linking.
InterfaceWeb UI with a start screen that checks the tools, a progress flow, Summary and Investigator modes, detail views with evidence line viewer, offline report. Dark and light themes.
PackagingHardened two-container Compose stack, self-contained installer, multi-architecture image (amd64 and arm64) published to GHCR by CI.
Not yetSyslog, CSV and tshark JSON are stored but not analyzed. Comparing two captures (the v1 baseline feature) is not rebuilt. Tool versions are not yet written into each record.

The full commit history is in the repository.
