Usage

Use the web UI for investigations, or the rehub command for scripted runs. Both produce the same record.

Start an investigation

Drop evidence on the start page, or press Choose files. A packet capture, Zeek logs, Suricata alerts, PLC project files, or a zip or tar of these all work. Several files can go into one investigation.

For each PLC file you can type the controller IP it belongs to. ReHub uses that to link network writes to the program. Then press Analyze.

No evidence handy? Press Try the demo. It analyzes a built-in synthetic pump station capture with a rogue device. The same files are in samples/ in the repository, one of each evidence type.

Watch it work

While the tools run, the flow shows the pipeline: evidence goes to Zeek, Suricata and tshark, then to the ReHub engine, then to the five stages you will read.

Summary

Summary is the optional condensed view for someone who needs the story, one toggle away in the header. It opens with what happened, then the key detections, each with its tool lanes (filled means that tool saw it), then the five-stage flow.

Investigator

Investigator is the default view. It walks the flow stage by stage, and a write command shows the register and value it set. Each stage names the question it answers.

Assets: what devices are on this network?

Every device with its IP, a MAC address and vendor where known, its role (client or controller), and the PLC program matched to it. MAC attribution uses ARP replies first. Traffic through a router shows the router's MAC, and ReHub says so instead of guessing.

Communication: who talks to whom?

Clients on the left, controllers on the right. A dashed colored line means a detection was raised on that conversation. Select a row and Show packets for the packets behind it.

Detections: what looks wrong?

Each detection has a severity (never shown by color alone), the tools that saw it, the ATT&CK for ICS candidates, the effect on the PLC program, and the evidence.

Evidence: what proves it?

Show source line opens the exact line in the tool output, with its neighbors. Download file gives the original file. Evidence is only ever served as a download, never rendered.

Report: who needs what?

A single document with the answer, the detections, the assets and the limits. Print it, or download it as one offline HTML file with no scripts.

Themes and small screens

The sun and moon button switches between dark and light. The choice is remembered in the browser. The layout works down to a phone width.

Command line

The rehub command is inside the image. Global option: --data DIR (default $REHUB_DATA or ~/.rehub) is where investigations are stored.

CommandParameters
rehub analyze FILES...--plc-ip NAME=IP (repeatable) tells ReHub which controller a PLC file belongs to. --timeout S limits each tool run (default 1800).
rehub show IDPrint a stored investigation.
rehub doctorCheck storage and the three tools. --quick skips the self-test on the built-in capture.
rehub serveRun the web UI and API. --host H (default $REHUB_HOST or 127.0.0.1), --port P (default $REHUB_PORT or 8080), --auth.
rehub tokenPrint the access token. --rotate makes a new one.
rehub gatewayThe TCP forwarder used by the Compose stack. --listen H:P, --upstream H:P.

Example: analyze a capture and a PLC file

Run it in a throwaway container with no network. Evidence is mounted read-only; results go to ./data.

docker run --rm --network none --read-only --tmpfs /tmp --user "$(id -u):$(id -g)" \
  -v "$PWD/samples:/in:ro" -v "$PWD/data:/data" ghcr.io/ani07-05/rehub-engine:latest \
  rehub --data /data analyze /in/capture/ot-demo.pcap /in/plc/pump.st --plc-ip pump.st=10.0.0.20

It prints the investigation id. Read it back with rehub --data /data show ID.

Example: run the stack with sign-in

sh install.sh --auth

Sign-in is off by default because ReHub is local only. With --auth a sign-in link is printed. The token becomes an HttpOnly cookie.
